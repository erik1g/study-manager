# Überblick für Entwickler

Der Study Manager ist ein TypeScript-Monorepo (pnpm-Workspaces). Er soll für **möglichst viele Studierende** funktionieren – Hilfe ist willkommen, von Tippfehlern bis zur Anbindung einer neuen Hochschule.

## Wo fange ich an?

1. [Lokal starten](/entwickler/lokal-starten): das Projekt auf deinem Rechner zum Laufen bringen.
2. [Aufbau](/entwickler/architektur): wie die Teile zusammenspielen.
3. Such dir ein Issue mit dem Label [`good first issue`](https://github.com/erik1g/study-manager/labels/good%20first%20issue) oder eine Idee unter [Hochschulen anbinden](/entwickler/hochschulen-anbinden).
4. [Mitmachen](/entwickler/mitmachen): Branches, Commits, Pull Requests.
5. [Tests](/entwickler/tests) und [Releases](/entwickler/releases).

## Die Teile

| Ordner | Inhalt |
|---|---|
| `apps/web` | Web-App (React 19, Vite, React Router, FullCalendar) |
| `apps/server` | API, MCP-Server und Hintergrundjobs (Node.js 24, Fastify, Drizzle, pg-boss) |
| `packages/ui` | Bausteine und Design („Snug Simple“) – siehe [Design-System](/entwickler/design) |
| `packages/shared` | Gemeinsame Typen und Regeln (Rollen, Entwürfe, Modulschema) |
| `apps/e2e` | End-to-End-Tests mit Playwright |
| `apps/docs` | Diese Dokumentation (Docusaurus) |
| `infra` | Dockerfiles, Caddy, Testdaten, Skripte |
| `docs/adr` | Architekturentscheidungen |
| `CONTEXT.md` | Glossar der Begriffe (Fach, Deadline, Aufgabe …) |
| `.claude/` | Anweisungen für Claude und Entwickler (Commit-Regeln, Prüfbefehle, Regeln je Bereich), von Claude Code automatisch geladen |

## Prinzipien

- **Keine KI auf dem Server.** Claude arbeitet über MCP mit den Rechten des Nutzers; was früher automatisch ging, steht in einem Arbeitseingang. Siehe die ADR `0002`.
- **Nur Bausteine aus `@study/ui`** in der Oberfläche (eine CI-Prüfung achtet darauf).
- **Selbst hosten, einfach halten.** Ein Docker-Compose-Projekt, ein Reverse Proxy davor.
- **Erfundene Testdaten.** Keine echten Personen, Hochschulen oder Zugangsdaten in Tests, Beispielen und Doku.
