# Button

`import { Button } from "@study/ui"`

Ein Knopf löst etwas aus: speichern, anlegen, hochladen. Sein Text sagt als **Verb**, was passiert. Führt er nur woandershin, ist er ein [LinkButton](./link-button).

```jsx live
function Beispiel() {
  const [saving, setSaving] = useState(false);
  return (
    <div style={{ display: "flex", gap: 10, flexWrap: "wrap" }}>
      <Button variant="primary" icon="check" loading={saving} onClick={() => { setSaving(true); setTimeout(() => setSaving(false), 1500); }}>
        Speichern
      </Button>
      <Button>Abbrechen</Button>
    </div>
  );
}
```

| Variante | Wofür |
| --- | --- |
| `primary` | die **eine** Hauptaktion einer Ansicht |
| `secondary` | alles andere (Standard) |
| `soft` | freundliche Nebenaktion auf einer Farbe, z. B. „Mit Claude“ (`tone`) |
| `danger` | Löschen, Verlassen, Abmelden |
| `ghost` | leise Aktionen in Leisten und Listen |

- Mit `loading` statt eigener Spinner – der Knopf ist dann gesperrt und sagt Screenreadern, dass er arbeitet.
- `type="submit"` nur im Formular; sonst ist ein Button immer `type="button"`.
- Für Elemente, die kein `Button` sein können, gibt `buttonClass({ variant, size })` die Klassen.

## Barrierefreiheit

- Ein echtes `<button>`: mit Tab erreichbar, mit Enter und Leertaste auszulösen.
- Deutlicher Fokusring (3 px, `--ui-focus`), nur bei Tastaturbedienung.
- Mindestens 44 px hoch in `md`; `sm` nur, wo eine Maus wahrscheinlich ist.
- `loading` setzt `aria-busy` und sperrt doppelte Klicks.
